# Документация проекта Kanban Board

Это основная документация по проекту. Здесь собраны ключевые сведения об архитектуре, быстром запуске и дорожной карте для развития.

## Содержание

- `README.md` — главный файл проекта с быстрым стартом и описанием функциональности.
- `docs/INSTALLATION.md` — подробная инструкция установки.
- `docs/DEVELOPMENT.md` — гайд для разработчиков и работа с миграциями.
- `docs/API.md` — структура API, OpenAPI / Swagger и список маршрутов.
- `docs/ARCHITECTURE.md` — архитектура проекта и основные компоненты.
- `docs/CONTRIBUTING.md` — правила и рекомендации по контрибьютингу.
- `docs/MAINTENANCE.md` — руководство по сопровождению и поддержке.
- `docs/INDEX.md` — индекс доступной документации.
- `docs/legacy/API_legacy.md` — архивная версия API-документации.

## Что описано здесь

1. Структура проекта.
2. Архитектура backend и frontend.
3. Как расширять функционал.
4. Как работать с админ-панелью.
5. Куда писать, если нужно поддерживать приложение.

## Быстрый путь

- Если вы хотите начать работу с проектом, откройте `README.md`.
- Если вы добавляете новый функционал или исправляете баг, откройте `docs/MAINTENANCE.md`.

## Ключевые файлы

- `app.py` — приложение FastAPI, запуск и сидирование данных.
- `database.py` — настройка подключения к SQLite и создание сессий.
- `models/models.py` — модели базы данных.
- `routers/` — HTTP-маршруты приложения.
- `templates/` — Jinja2-шаблоны пользовательского интерфейса.
- `services/` — вспомогательные сервисы, бэкапы и экспорт.
- `config.py` — переменные окружения и настройки приложения.

## Важный лайфхак

Все изменения, связанные с пользовательской логикой, должны сопровождаться обновлением документации:

- новая страница в админке → описание в `README.md` + `docs/MAINTENANCE.md`;
- изменение модели БД → описание полей и возможных сценариев работы;
- новые HTTP-маршруты → краткий список в документации.
